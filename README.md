## 💎 О проекте GROKSON

**GROKSON** — это полнофункциональное веб-приложение нового поколения, созданное в строгом премиальном тёмном дизайне: глубокий чёрный фон (`#050505`), контрастная белая типографика, деликатное холодное кибер-свечение (`#00F0FF`) и футуристичный маскот-робот в чёрном худи.

### Ключевые возможности
1. **Персональный ИИ Grokson**:
   - Отвечает на любые вопросы, пишет код, анализирует данные, генерирует идеи.
   - Поддержка форматирования Markdown, подсветки блоков кода и копирования в один клик.
   - Возможность перегенерации (`Regenerate`) и повтора при сбоях сети (`Retry`).
2. **Бесплатный стартовый пакет 20 000 токенов**:
   - При регистрации каждый пользователь получает **20 000 токенов**.
   - Атомарное списание токенов на сервере по формуле: `prompt_tokens + completion_tokens`.
   - При исчерпании лимита отображается стильное окно с кнопкой пополнения по промокоду.
3. **Промокодная система**:
   - Выпуск кодов формата `GROK-XXXX-XXXX` на 10 000, 20 000, 50 000 или произвольное количество токенов.
   - Одноразовые и многоразовые коды с ограничением числа активаций и сроком действия.
4. **Защищённая панель администратора (Admin Panel)**:
   - **Dashboard**: метрики пользователей, использованных/выданных токенов, запросов и графики за 7 дней.
   - **Users**: база пользователей с возможностью ручного начисления токенов.
   - **Tokens**: детальный аудит всех транзакций.
   - **Promo Codes**: генератор промокодов с кнопкой быстрого копирования.
   - **AI Settings**: переключение моделей (`grokson-v1`, `gemini-2.5-flash`, `gigachat-lite`), безопасная маскировка API-ключа, проверка связи в реальном времени (`Test connection`).
   - **API & Security**: журнал аудита администратора и мониторинг ограничений.

## 🛡️ Архитектура безопасности: почему API-ключ НЕЛЬЗЯ хранить во Frontend

Критическое правило безопасности: **API-ключ AI-провайдера НИКОГДА не должен попадать во frontend.**

- Любой код, отправляемый в браузер (включая переменные с префиксом `VITE_` или `REACT_APP_`), может быть извлечён через DevTools за 5 секунд.
- При публикации на GitHub Pages исходный или собранный JS-бандл является публичным. Если в него попадёт секретный ключ, злоумышленники опустошат ваш баланс или заблокируют аккаунт.
- **В GROKSON реализована изолированная архитектура**:
  1. Frontend (React + Vite) — статический SPA, который общается исключительно с защищённым эндпоинтом `/api/*`.
  2. Backend (Node.js + Express) — хранит секретные переменные окружения, проверяет авторизацию и токены пользователя, и лишь затем отправляет защищённый серверный запрос к AI-модели.
  3. API-ключ скрыт от клиентской части, а в панели администратора маскируется (`••••••••••••`).

## 🚀 Как запустить локально (Full-Stack)

1. Клонируйте репозиторий:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd grokson
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Настройте файл окружения:
   ```bash
   cp .env.example .env
   ```

4. Запустите в режиме разработки:
   ```bash
   npm run dev
   ```
   Сервер запустится на `http://localhost:3000`. В режиме разработки Vite монтируется как middleware, обеспечивая работу и API, и интерфейса на одном порту.

5. Сборка для продакшн:
   ```bash
   npm run build
   npm start
   ```

## 🌐 Развертывание Frontend на GitHub Pages

Репозиторий уже настроен для корректной работы с GitHub Pages:
- `vite.config.ts` настроен с `base: './'` (относительные пути без белого экрана).
- В проекте используется Hash-маршрутизация (`#/`, `#/chat`, `#/admin`), что исключает ошибки `404 Not Found` при перезагрузке страниц на GitHub Pages.
- Создан файл `public/404.html` для автоматического редиректа прямых ссылок.
- Добавлен автоматический GitHub Actions workflow: `.github/workflows/deploy.yml`.

### Шаги публикации на GitHub Pages:
1. Загрузите код в ваш репозиторий на GitHub.
2. Перейдите в **Settings** репозитория -> **Pages**.
3. В разделе **Build and deployment** выберите:
   - **Source**: `GitHub Actions`.
4. При каждом пуше в ветку `main` или `master` Actions автоматически соберёт проект и развернёт его.
5. Для подключения к удалённому бэкенду нажмите на иконку настроек API в шапке сайта и укажите URL вашего развёрнутого бэкенда (или настройте `VITE_API_URL` в секретах репозитория).

## ⚙️ Развертывание Backend

Бэкенд представляет собой легковесный сервер на Express + SQLite (или Postgres/Cloud SQL при необходимости):

1. **Docker / Cloud Run / VPS**:
   - Скомпилируйте сервер: `npm run build`
   - Запустите команду `npm start` (запускает `dist/server.cjs`).
2. **Платформы развёртывания**:
   - **Render / Railway / Fly.io / VPS**:
     - Build Command: `npm install && npm run build`
     - Start Command: `npm start`
     - Port: `3000`
   - **CORS**: Бэкенд уже содержит гибкие правила CORS, принимающие запросы с доменов `*.github.io` и localhost.
